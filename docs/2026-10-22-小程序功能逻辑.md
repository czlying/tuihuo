## 二、状态模型

底层 `status` 只有三种，`considering` 是待退订单上的布尔标记：

| 页面名单 | 条件 | 说明 |
|---|---|---|
| 想退货名单 | `status=pending && considering=true` | 还在犹豫，尚未决定退 |
| 退货名单 | `status=pending && considering=false` | 已决定退，尚未标记上门取件 |
| 上门取件 | `status=applied` | 已申请退货，等待快递取走 |
| 已取货 | `status=picked` | 终态 |

> `overdue` 不落库，读取时按 `deadline < 今天` 派生。

## 三、主流程（四级流转）

```
想退货名单
  └─ 点「决定退」→ 弹出取件码输入框 → 保存 pickupCode
       └─ 进入 退货名单
            └─ 点「标记上门取件」→ 确认 + 选取件时间
                 └─ 进入 上门取件（status=applied）
                      └─ 点「取货」→ 进入 已取货（status=picked）
```

- **决定退**：只把 `considering` 置 false，并保存用户输入的 `pickupCode`；不会直接变成 applied。
- **标记上门取件**：写 `status=applied`、`appliedAt`、`shipDeadline=今天+7`、`pickupTime`，清 `considering`。
- **取货**：写 `status=picked`、`pickedAt`。
- **移回退货**：编辑上门取件订单时选「移回退货」，回到 `pending + considering=false`，清 `appliedAt/pickedAt/shipDeadline`。

### 新建订单
- 勾「想退货」→ `pending + considering=true` → 想退货名单
- 不勾 → `pending + considering=false` → 退货名单
- 不再自动变成已申请

## 四、首页看板

### 顶部
- 全部总额 / 总笔数：想退 + 退货 + 上门取件 + 已取货四个名单合计
- 右侧「今日双鱼运势」卡片：文本框固定三行，完整文案超出按字数补「…」（卡片尺寸不变）；点卡片弹出浮层看全文，点遮罩或右上角 ✕ 关闭。数据仍走云函数代理取聚合数据星座运势（Key 存云函数环境变量 JUHE_KEY，前端不接触）；成功覆盖、失败/超时保持兜底；同一天只在没有缓存时请求一次——缓存写本地存储（`fortune_cache_v1`），冷启动也复用，跨天自动失效；只缓存接口成功取到的文案，失败不写缓存，下次进页面会重试
- 设置页「运势接口自检」：一键调用 `api` 云函数的 `horoscopeProbe` 动作，直接返回 Key 是否读到 / 是否带空格 / HTTP 状态 / 聚合数据错误码 + 中文结论与下一步操作。用于排查「配了 Key 为什么不生效」，不影响任何设置与数据
- **今/明到期条**：想退、退货、上门取件三个名单的今天/明天到期笔数
- 顶部hero下方常驻「今/明到期」提醒条：想退 / 退货 / 上门取件三个名单的笔数

### 四个名单
| 名单 | 默认 | 操作 |
|---|---|---|
| 想退货名单 | 展开，点标题行收起 | 搜索、决定退（录取件码）、左滑删除 |
| 退货名单 | 展开，点标题行收起 | 标记上门取件（选取件时间）、左滑删除 |
| 上门取件 | 展开，点标题行收起 | 取货、左滑删除、搜索 |
| 已取货 | 展开，点标题行收起 | 搜索、左滑删除 |

- 四个名单头部统一为单行：左侧标题 + 粉色圆形角标，右侧金额、笔数与收起指示；点标题行展开/收起，四个名单行为一致
- 上门取件与已取货沿用分页 + 搜索
- 每行显示凭证缩略图（无图占位）、商品、平台、金额、日期、取件码/取件时间

## 六、录入与编辑

### 字段
平台、商品名（≤60 字）、金额（分存储，展示元）、申请退货日期、退货天数、最晚可退日、最晚可退时间（默认 00:00:00）、取件码、订单编号、退货原因、凭证、备注（页面暂隐藏）。

### 校验
- 商品名必填
- 金额 ≥ 0
- 申请退货日期必填
- 退货天数 0–365 整数
- 订单编号：有值时服务层查重（同时兼容旧 `returnNo`），重复硬拦截；空值直接保存
- 最晚可退日：可自动算（申请日期 + 天数）或手动指定

### OCR
- 云函数 `api` 调腾讯云 OCR
- 提取商品名/金额/收货日期/平台/订单号/退货原因/取件码/取件时间
- 平台识别走规则库；证据不足返回 unknown
- 识别截图自动追加到凭证
- **取件码识别（本期只支持拼多多）**：标签命中为高置信；拼多多额外走「6 位数字取离标签最近」兜底，低置信时提示「请核对取件码」；只回填空的取件码输入框
- 超过 5MB 的识别截图先压缩再上传
- `OCR_RULE_VERSION` 在 Console 打印

## 七、云开发

### 集合
- `orders`：订单
- `settings`：单用户设置
- `userPlatforms`：用户自建平台

### 云函数
- `api`：health / OCR / whoami 等 action 路由
- `timerRemind`：定时提醒；08:00 主触发 + 14:00 兜底，按档位幂等

### 权限
`_openid == auth.openid`；业务主键用 `uid`，`_openid` 只做安全规则。
