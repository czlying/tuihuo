- 物流状态条里的时间 `12:10:50`、`12:18:19` 与 4 位码形近。
- `11.11` 会被读成金额或价格。

**③ 数字串清单 + 含义**

| 数字串 | 含义 | 是否可能是取件码 |
|---|---|---|
| `4天14小时` | 填单号时限 | 否 |
| `18235678754` | 取件地址中的手机号（11 位明文） | 否（长度不符，且是电话） |

- 是否依赖「上门取件」：**此页就是选方式页**，四个选项都在（含上门取件），但**尚未预约**，所以仍未出码。

- `上门时间` 是**相对日期**（明天 + 时段），不能写进取件时间字段。
- `预估费用 ¥0 ¥5.55` 两个金额紧邻，易把 `5.55` 当实付。
- 取件地址里含 11 位手机号，与订单号片段形近。
- 四选卡文字很短（`去服务点`/`去快递柜`/`自行退回`），容易被当成商品名或按钮标签。
- `《拼多多退货服务协议》` 里的品牌词是判定平台的强证据，但 OCR 可能把书名号吃掉。

**③ 数字串清单 + 含义**

| 数字串 | 含义 | 是否可能是取件码 |
|---|---|---|
| **`2281`** | **取件码（4 位纯数字）** | **是** |
| `明天09:00-11:00` | 上门时段 | 否（相对日期+区间） |
| `富河园23号楼4单元6层461` | 门牌号 | 否 |
| `¥0` | 预估费用 | 否 |

**④ 取件码是否出现**：**是**（1/1），且是唯一出现取件码的页面类型。
- 是否依赖「上门取件」：**是**。本页卡片头即「本次寄件服务享受官方补贴」= 上门取件分支。
- 是否依赖商家已同意退货：**是**。进度条已过「商家处理」。

**⑤ 版面位置**
- 标签名：`取件码`（黑色小字）
- 值：**大号红色数字**，与标签**同一行**，紧贴标签右侧
- 相邻组件：**上方**是红字取件时段（`明天09:00-11:00快递员将上门取件`），**下方**是 `请在快递员上门后出示`
- 是否可复制：**无复制按钮**（与订单号的 `复制` 不同）
- 是否条码/二维码：**无**
- 是否隐藏位数：**不隐藏**，4 位全显

**⑥ OCR 易错点**
- 「取件码」与 `2281` 同行，OCR 可能输出 `取件码2281` 一整串，需按标签切分。
- `2281` 是 4 位数字，与时段 `09:00`、`11:00`、门牌 `461`、费用 `0` 形近。
- 取件地址里 `富河园23号楼4单元6层461` 含大量数字，紧邻取件码下方两行 —— **最容易误抓的位置**。
- `明天09:00-11:00快递员将上门取件` 一整行连写，时段与文字粘连，容易把 `0900` 或 `11:00` 当码。
- 下方 `请在快递员上门后出示` 紧邻「取件码」下方，若按「标签下一行取值」会取到这句说明文案。

## 4. 跨页通用规则（本目录可支撑的部分）

### 4.1 取件码出现条件

```
出码  ⟺  page_type = pickup_code_page
        ⟺  售后已过「商家处理」 且 退货方式 = 上门取件 且 已完成预约 且 快递员未取走
```

- **订单详情页默认无取件码**：本目录 4/4 pdd 订单页均无，且这些页根本没有售后入口状态。
- **取件码只在「售后 + 上门取件」分支出现**：本目录中唯一出码页的卡片头就是「本次寄件服务享受官方补贴」。
- **自行寄回无取件码**：本目录 only 有「自行退回 并填写单号」这一**选项**（拼多多 (2).jpg），未观测到它的落地页 → 该结论在本目录只有**选项级**证据，落地页**未观测**。
- **去服务点 / 去快递柜**：同样只在选项级出现，落地页**未观测**。

### 4.2 数字串格式特征（本目录实测）

| 类型 | 格式 | 本目录样本 |
|---|---|---|
| 拼多多订单号 | `YYMMDD-15位数字`（6+1+15 位） | 261015-521320568353024 / 261022-633360903713024 / 261022-436710960673024 / 261011-360343170593024 |

| 手机号 | 11 位，脱敏形如 `153****2037`；明文形如 `18235678754` | 多张 |
| 上门时段 | `明天`/`今天` + `HH:MM-HH:MM` | 品duoduo、拼多多(2) |

### 4.3 哪些数字绝对不是取件码（本目录逐条对得上）

| 数字 | 依据 |
|---|---|
| `261015-521320568353024` 这类订单号 | 带连字符、长度 22，且带「订单号：」标签 |
| 11 位手机号 `18235678754` / `153****2037` | 长度与「号码保护中」/ 收件人上下文 |
| 门牌号 `23号楼4单元6层461` | 紧跟「号楼/单元/层」汉字 |

| 时间 `12:10:50` `09:00-11:00` | 带冒号 |

| `4天14小时` `15小时` | 带「天/小时」 |

## 5. 抽取 schema（供后续 OCR 使用）

> **实现契约以 `docs/2026-10-20-OCR平台识别规则手册.md` §15.6 为准**（当前 11 字段）。
> 本节保留「样本能提供哪些字段、哪些字段本目录根本没有」的证据结论。

当前实现的 11 个字段（缺值空串，不给 null）：

```json
{
  "platform": "pdd | taobao | jd | express | unknown",
  "platform_conf": "high | mid | low",
  "page_type": "order_detail | after_sale_detail | pickup_code_page | unknown",
  "has_pickup_code": true,
  "pickup_code_raw": "",
  "pickup_code_normalized": "",
  "low_confidence": false,
  "order_sn": "",
  "express_company": "",
  "pickup_time": "",
  "address": ""
}
```

字段来源（本目录可对应的部分）：

| 字段 | 取值来源 | 本目录示例 |
|---|---|---|
| `platform` / `platform_conf` | 见 §1.4 判定顺序 | pdd / high、taobao / high |
| `page_type` | 见 §2 分类依据 | pickup_code_page、order_detail |
| `has_pickup_code` | 见 §4.1 出码条件 | 品duoduo=true，其余 false |
| `pickup_code_raw` | 取件码标签后原样字符（4~6 位） | `2281` |
| `pickup_code_normalized` | 仅 `O/o→0`、`l/I→1` 后；低置信留空 | `2281` |
| `low_confidence` | 区块分 <0.6 或字符断裂 | false |
| `order_sn` | 「订单号：」后原样（含连字符） | `261015-521320568353024` |
| `express_company` | **本目录无来源**（只有代收点「兔喜」，不是承运商） | `""` |
| `pickup_time` | 「上门时间/取件时间」标签值或「…快递员将上门取件」句子 | `明天09:00-11:00快递员将上门取件` |
| `address` | 「取件地址/退货地址」标签值 | 通州区富河园23号楼… |

三处本目录暴露的取值难点：
1. `express_company` 在订单详情页**根本没有**（要进「查看物流」二级页才出现）→ 本目录 7 张里应全部为空，若抽出值就是误抽。
2. `order_sn` 必须**保留连字符**，否则与 15 位裸数字混淆；连字符长串也绝不能被切出前 6 位当取件码。
3. 方式页（after_sale_detail）出现「上门取件」四个字**不等于已选上门取件**，取件码仍应为空。

> 说明：早先草案里的 `express_no`、`pickup_type` 两字段已按 2026-10-28 22:11 的严格 JSON 契约移除，
> 见 `docs/2026-10-28-OCR识别修改记录.md` R-11（回滚）与 R-12。

### 6.2 规则覆盖不到 / 易错

| # | 问题 | 依据 | 影响 |
|---|---|---|---|
| 1 | 15 位订单号被切成 4~8 位片段后，会「长出一个取件码」 | 4 张订单页都存在长数字 | 假阳性，高危 |
| 2 | `复制` 按钮归属不唯一 | 订单号旁的 `复制`、商家地址旁的 `复制` | 若按「复制旁找码」会抓错 |
| 3 | 取件码下方两行就是含门牌号的取件地址 | 品duoduo | 若标签跨行取值可能落到地址 |
| 4 | 「取件码」下一行是说明文案 | 品duoduo 的 `请在快递员上门后出示` | 按「下一行取值」会取到文案 |
| 5 | 相对日期无法转绝对日期 | `明天09:00-11:00`、`明天 09:00-11:00` | 取件时间字段只能存原文 |
| 6 | 文件名与平台无关 | `拼多多.jpg` 实为淘宝 | 任何按文件名判平台的逻辑都不可靠 |
| 7 | `预估费用` 有两个金额 | 拼多多 (2)：`¥0` 与 `¥5.55` | 金额抽取易取错 |
