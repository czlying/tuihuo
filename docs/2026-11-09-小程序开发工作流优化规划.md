## 一、文章讲了什么（浓缩版）

文章把做小程序拆成三层：**基础版（能用）→ 进阶版（好看）→ 正式版（上线）**。

### 1.1 基础版：四步做出能跑的版本

| 步 | 做什么 | 关键点 |
|---|---|---|
| ① | 说清需求 | 只描述四件事：**用途、使用对象、功能（页面清单）、视觉风格**。不要一次写很长 |
| ② | 分步完善 | 先生成可用版，再按「**功能 → 存储 → 优化 → 自查**」四句话分次迭代；一次只改一个问题，说清「当前效果」和「期望效果」；视觉问题直接贴截图比说「更好看一点」有效 |
| ③ | 接云服务 | 关掉再打开数据还在，就必须存云端。入口：预览页左上角「云服务」或 设置 → 数据管理 → 应用。**按「可开云服务的应用数」+「单应用资源点」两份额度计量，资源点按月刷新，用尽该应用云服务暂停** |
| ④ | 发布试用版 | 产物卡「分享」→ 创建试用版小程序 → 微信授权 → 得小程序码扫码体验。**试用版 14 天有效，不能直接转正式版** |

自查那句提示词值得抄下来：*「所有页面是否都已在配置里登记；有没有用到小程序不支持的写法；有没有写死的文字该改成配置；有没有需要用户授权的信息」*。

### 1.2 进阶版：Ardot 五步（设计稿 → 代码）

概念图 → 按微信规范修（顶部胶囊区不能放元素、底部留安全区、点击区 ≥44×44px、正文 14~16px、辅助文字 ≥12px）→ 图转 UI（产出可编辑图层）→ 抽组件库 + 生成 `DESIGN.md` → 把设计稿链接 + 组件库 + `DESIGN.md` 一起给我，照着写代码。

两条最实用的警告：
- **设计稿只说明界面长什么样，不会写清楚按钮行为** —— 功能逻辑、页面跳转、存储要求必须另外单独说。
- **改完代码不会自动同步线上**，要手动点「更新」。

### 1.3 正式版：四步上线

注册账号（选主体类型）→ 备案 + 类目 + 认证 → 在分享面板「绑定已有小程序账号」扫码授权 → 发体验版或正式版 → 提交审核（审核由微信执行）。文章特别点了一句：**个人主体的正式版不能被搜索，只能靠分享链接打开**（与你的现状一致）。

## 二、你现在手动做的事，能自动化几件

这是本次规划的账本。✅ 我能直接干；⚠️ 我能做但要你点一次确认；❌ 只能你来。

| # | 你原来手动做的 | 现在靠什么自动 | 状态 |

| 2 | 控制台手建集合、手建 `orders` 索引 | `cloud_db_write_struct`（读写结构）、`cloud_db_read_struct`（先查再改） | ✅ 已无待办（见第三节） |
| 3 | 翻控制台看云函数在不在、是不是新版 | `cloud_fn_list` / `cloud_fn_info` / `cloud_env_list` | ✅ 全自动 |
| 4 | 云函数超时 3s → 20s | 无对应命令，但**实测已是 60 秒** | ✅ 已闭合 |
| 5 | 配 08:00 / 14:00 定时触发器 | 无对应命令 | ❌ 控制台手动（已配好，平时不动） |
| 6 | 编译、真机预览、扫预览码 | `auto_preview`（预览直推微信，不出二维码文件）、`create_preview_qrcode`、`simulator_open_page`、`simulator_refresh` | ✅ 全自动 |
| 7 | 手动点页面验证交互对不对 | `automation_element_action`（真实点击/输入/滚动）、`automation_page_action`、`automation_navigate`、`automation_evaluate` + `simulator_screenshot` 截图留证 | ✅ 全自动 |
| 8 | 排查前端报错 / 接口失败 | `get_simulator_console`、`get_simulator_network`、`automation_wx_api` | ✅ 前端可查（**云函数日志仍需控制台**） |
| 9 | 开发者工具点「上传」出体验版 | `upload` | ⚠️ 你点一次确认 |
| 10 | 后台配订阅消息模板 | `cloud_query_msg_push` / `cloud_manage_msg_push` | ⚠️ 能配，但额度与授权交互仍要设计 |
| 11 | 提审、类目、备案、隐私指引、版本发布 | 无 | ❌ 永远你在公众平台操作 |

**结论：11 项里 5 项完全自动，3 项我做完你点一下确认，只剩「定时触发器 + 云函数日志」和平台事务（提审备案）必须你亲自来。** 你在开发者工具里来回点的量，实际可以压缩掉八成。

## 六、你永远要亲自做的（谁也替不了）

1. **开发者工具登录态过期时扫一次码**。现在有效，平时不用管。
2. **确认弹窗点「允许」**。我发起上传、写库结构、推预览时，开发者工具会弹窗等你确认 —— 微信的安全设计，绕不过。
3. **控制台两件事**：定时触发器、云函数运行日志（CLI 没有这两样；超时已不需要动）。
4. **公众平台侧全部事务**：类目、备案、认证（300 元/年，只在做虚拟支付时才花）、隐私指引、提交审核、版本发布。
5. **真机肉眼看**：iPhone 刘海遮挡、Android 返回手势、字号观感。自动化只跑模拟器，不等于真机。

## 七、为什么不迁到 WorkBuddy 云服务（写清否决理由）

| 对比项 | 微信云开发（现状） | WorkBuddy 云服务 |
|---|---|---|
| 数据库 / 存储 | ✅ 已有 | ✅ 有（数据要从零迁） |
| **自建云函数** | ✅ `api` / `timerRemind` | ❌ **没有** |
| **定时触发器** | ✅ 08:00 + 14:00 | ❌ **没有** |
| OCR（云函数调腾讯云 OCR） | ✅ | ❌ 只能走大模型识图，现有识别规则全部作废、成本结构变化 |
| 预览发布 | 开发者工具 / 公众平台 | ✅ 全在 WorkBuddy 内，最省事 |
| 迁移成本 | — | 数据层重写 + 凭证图迁移 + 云函数作废 |

**判断依据只有一条：提醒是产品核心，而提醒必须靠定时触发器。** 代价（砍掉核心功能）远大于收益（发布顺手一点）。

## 九、默认约定（不用你每次拍板）

- **改 OCR 规则**：默认按 S1–S4 全链路走，含部署与点击验证；只多两次确认弹窗。
- **凡涉及云函数改动的交付**：必须附「部署后版本号」证据，不许只报代码改完。

- **破坏性操作**（删集合、删索引、删云函数、删订单数据）：一律先读后列清单，明确确认后才动；默认保持现状。
- **新项目**：默认走 WorkBuddy 全托管链路，除非需求里有定时任务或自建服务端逻辑。
